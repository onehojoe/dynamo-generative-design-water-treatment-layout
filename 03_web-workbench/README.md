# 03 · 웹 워크벤치 — 브라우저에서 돌리는 배치 스터디 / Web Workbench

`2500726 정수장 python 최적화 v1.dyn`(강의 2일차 응용 그래프의 발전형)의 배치 로직을
**Revit·Dynamo 없이 브라우저에서** 그대로 체험하는 교육용 도구입니다.

An interactive reproduction of the layout logic — run the placement study
**in a browser, no Revit / Dynamo required**.

## 실행 / Run

**`RUN.bat` 더블클릭.** 그게 전부입니다 — 서버·설치·인터넷 불필요(데이터는 `js/data.js`에 내장).
수동 실행: `index.html`을 브라우저로 열기.

## v0.4에서 더해진 것 (2026-08-25) — 입력 UV · 계통 4목표 · 자동 추론

### 1. 입력: 시드 11 → **UV 22** (양쪽 다 남아 있다)

시드는 **불연속**이다. 59와 60의 배치가 완전히 다르다 — GD의 교배·변이가 의미를 잃어
사실상 랜덤 탐색이 된다. UV는 새 좌표계가 아니라 **dyn 후보점의 본래 파라미터**(`0..1` 격자)로
돌아간 것이다(`u = i/(n-1)`). 막힌 자리는 **가장 가까운 유효점으로 수복**한다.

> 실측(게이트 #9): 입력을 한 단위 흔들었을 때 평균 |Δ총점| — **UV 0.77 vs 시드 7.97 (10.3배)**.

### 2. 연결망: dyn 8쌍 → **계통 v2 (L1~L12 + 동선 2)**

★dyn 8쌍에는 **[8] 역세척펌프장과 [13] 관리동이 없다.** 두 시설은 어디에 놓아도 점수가
변하지 않는다 — 그 시드는 순수 노이즈였다(게이트 #5·#6이 이 사실을 실측으로 고정한다).

계통 v2는 정수장 공정으로 이를 메운다: 본류 6(`1→2→3→4→5→6→7`) + 역세 2(`7→8→4`) +
배출수·슬러지 3(`4→9`, `3→10`, `11→12`) + 반송 1(`9→1`) + 차량동선 2(`12→정문`, `13→정문`).
**11개 시설 전부가 채점에 참여한다.** 계통별 가중(본류 1.0 / 역세 0.45 / 배출수 0.40 /
반송 0.35 / 슬러지 0.30)으로 "같은 1m가 같은 값이 아님"을 반영한다.

### 3. 출력: Count·Length·Cost → **목표 4 + 제약 6**

| | 목표 | 방향 | 왜 |
|---|---|---|---|
| O1 | 가중 관로연장 | min | 관경 위계를 반영한 연장 |
| O2 | 가중 관로교차 | min | 교차 = 상하 분리 구조물 |
| O3 | 증설 여지 (최대 빈 사각형) | **max** | 정수장은 계열 단위 증설 — 남는 땅은 '한 덩어리'여야 쓴다 |
| O4 | 반출·관리 동선 | min | 케이크 덤프트럭 반출 · 관리동 정문 동선 |

제약: C1 배치수 11 · C2 겹침 0 · C3 경계이탈 0 · C4 이격 · **C5 자연유하 역행**(본류는 무동력
중력흐름이 원칙 — 표고가 없어 `[1]→[7]` 주축 투영으로 대리 측정) · C6 오존↔관리동 안전이격.

`Count`는 목표에서 **제약으로 강등**했고(상수 목표는 무의미), `Cost`는 Length와 상관계수 1이라
**O1 안으로 흡수**했다. 파레토는 이제 **4목표 동시** 비지배 판정이다.

### 4. 총점 — 기준안 대비 지수, 회계가 맞아야만 표시

관로 단가가 미확보이므로 **절대금액을 지어내지 않는다.** 기준안(dyn 저장 시드 배치)의 각 지표를
100으로 놓은 지수이고, 총점 = 가중평균 − 감점이다. **표에 적힌 기여의 합 − 감점 = 총점**이
맞지 않으면 화면이 그렇게 표시한다(게이트가 이 회계를 검사한다).

### 5. 추론 패널 — 왜 이 점수인가

9개 섹션: ①채점 회계 ②병목 진단 ③O1 내역(링크별 기여 %) ④O2 교차 목록 ⑤O3 증설 사각형
⑥O4 동선(관통 여부) ⑦제약 상태 ⑧대안군 안에서의 위치(순위·파레토·최고안 대비 델타·**목표 간
실측 상관**) ⑨다음 수. **LLM이 아니라 규칙 기반이며 숫자는 전부 평가기가 잰 값이다.**
`추론 리포트 MD`로 그대로 내보낼 수 있다.

### 6. 자동 개선 — 스스로 고쳐 가는 과정이 보인다

UV 모드에서 언덕오르기를 돌린다. 수(手)는 셋 — **이동**(한 시설 흔들기) · **교환**(두 시설
자리 맞바꾸기) · **회전**(90°). 총점이 오를 때만 받아들이고 보폭은 갈수록 줄인다.
받아들인 수마다 *무엇을 왜 바꿨고 어느 지표가 얼마 움직였는지*가 한 줄씩 쌓인다:

```
#15 이동 [5] (0.74,0.36)→(0.64,0.41) · 관로 -77↑ · 동선 -221↑ · 총점 113.6→148.8 (+35.20)
#45 교환 [5] ↔ [1] · 관로 -31↑ · 증설 +688↑ · 동선 -7↑ · 총점 164.9→171.3 (+6.40)
```

**전역 최적을 보장하지 않는다**(언덕오르기). 시작점을 바꿔 두세 번 돌려 비교하는 편이 낫다.

## 정직 고지 — 원본과 다른 점 / Known deviations

1. **Dynamo `List.Shuffle`은 시드가 없다** → 원본은 실행마다 결과가 달라질 수 있으나,
   워크벤치는 슬라이더 값을 시드로 쓰는 **결정적 셔플**이다(같은 시드 = 항상 같은 배치).
   교육 도구로서는 이쪽이 낫다고 판단해 의도적으로 바꿨다. → `docs/dyn-update-review.md` 참조.
2. **후보점 생성은 근사** — 원본은 Revit 바닥 Surface의 파라미터 그리드, 여기서는 대지경계
   bbox 그리드 + 내부 필터. 바닥면 ≒ 대지경계이면 실질 동일하나 검증하지 않았다.
3. **비용 단가 미검증** — Length→Cost 환산 계수의 실값을 원본 자료에서 확인하지 못해
   기본 1(=길이가 곧 비용)로 두었다. 화면의 빨간 배지가 그 표시다.
4. **Dynamo 실행값과의 수치 대조 미실시** — 이 도구는 "사양 이식"이며 "실행값 동치성"은
   Revit에서 원본 그래프를 돌려 대조해야 닫힌다.
5. **계통 v2의 링크 4건은 가정이다** — `L1`(착수정→혼화지) · `L7`·`L8`(역세) · `L12`(반송)는
   dyn·PPT 어디에도 없고 정수장 공정 지식으로 추가했다. dyn의 `1-3`·`6-12`는 계통상 설명되지
   않아 오기로 보나 **미확정**이다.
6. **계통별 가중은 미검증 가정** — 관경·유량 위계를 반영한 상대값이며 실단가표가 아니다.
7. **최소이격·안전이격 수치는 규정 원문 미대조** — 화면 기본값 10 m는 dyn을 따른 것이고
   법규 근거가 없다. C6 임계값은 기본 미설정(검사 안 함)이다.
8. **UV 수복이 항상 성공하지는 않는다** — 고정 순서 그리디라 마지막 큰 시설이 앉을 자리가
   아예 없는 경우가 있다(무작위 500건 중 10건, 전부 [13] 관리동 60.6×40.5 m).
   전 격자 전수 스캔으로 '가능한 자리 0'임을 확인했으므로 엔진 결함이 아니라 기하학적
   불가능이며, 그때는 미배치 → C1 실격으로 처리된다.
9. **O3·O4는 근사** — 증설 여지는 격자 근사(기본 64×64), 동선 우회는 관통 박스마다
   `(w+h)/4`를 더하는 근사이며 실제 도로 우회 계산이 아니다.
10. **표고가 없다** — 자연유하(C5)는 2D 주축 투영으로 **대리 측정**한 것이지 수리계산이 아니다.
   지형·절성토·낙차는 2단계다. → `docs/optimization-plan_v04.md`

## 데이터 재생성 / Regenerating data

```
python tools/extract_cache.py "<Remember 캐시를 가진 dyn 경로>"
```

dyn의 `Data.Remember` 캐시(대지경계·박스 11·출입 2·참조점 4)를 직독해 `js/data.js`를 다시 만든다.
⚠ 캐시가 빈 dyn(예: 캐시를 지운 배포 사본)은 쓸 수 없다 — 스크립트가 FAIL로 알려준다.
