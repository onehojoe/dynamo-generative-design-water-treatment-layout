## 0. 전제 — 왜 지금 순서를 정해야 하나

현행 그래프는 **GD 스터디로 돌 수 없는 상태**다(Input/Output 마킹 0개). 그런데 동시에
**셔플에 시드가 없어 같은 입력이 같은 출력을 보장하지 않는다.** 이 둘은 순서가 정해져 있다 —
①을 먼저 하면 "돌긴 도는데 같은 지점이 매번 다른 점수를 내는" 스터디가 되어, 솔버가 낸 결과를
믿을 수 없다. **②(재현성)를 먼저 닫고 ①(결선)을 여는 것이 맞다.**

검토 문서의 우선순위표는 "효과/난도" 기준이라 ①이 먼저였다. 실행 순서는 **의존성 기준으로 뒤집는다.**

## S2. GD Input/Output 결선 — 스터디가 비로소 돈다 (1~2시간)

| | |
|---|---|
| **작업** | IntegerSlider 11개 → `Is Input` 체크 / `Count`·`Length & Cost` 워치 노드 → `Is Output` 체크 |
| **주의** | Input 슬라이더의 **min·max·step이 곧 탐색공간**이다. 현행 0~100·step 1이면 조합이 101^11 — 솔버가 유의미하게 훑지 못한다. **step을 5 또는 10으로 올려 탐색공간을 먼저 줄일 것.** 이 판단이 이 단계의 핵심이며, 결선 자체보다 중요하다. |
| **작업 2** | Generative Design 창에서 Randomize 20~50안 → Optimize(세대 소수)로 확인 |
| **검증(닫는 조건)** | ① GD 창에 Input 11 · Output 2가 뜬다(스크린샷) ② Randomize가 서로 다른 대안을 만든다 ③ 같은 대안을 두 번 평가하면 같은 점수 — **S1이 닫혀 있어야 성립** |
| **교육 가치** | 강의 커리큘럼 03장 "Input으로 선언하지 않은 값은 탐색되지 않는다"의 **실물 예제**가 된다. 결선 전/후 캡처 2장이 그대로 교재 그림. |

## 워크벤치(웹) 쪽 후속 — v0.4 후보

dyn 업데이트와 짝이 되는 항목만 적는다. 우선순위는 dyn이 먼저다.

1. **대조표 화면** — dyn 실행값을 붙여넣으면 워크벤치 값과 나란히 비교(§검증 게이트의 도구화).
   이게 있어야 "실행값 동치성" 게이트를 사람 손 계산 없이 닫는다.
2. **박스 치수 정본 대조** — 캐시 vs `BOX.dwg` vs `.rvt` 3자 대조(카드 4번 항목). 아직 미실시.
3. **비용 단가 실값** — dyn·PPT 어디에도 환산 계수가 없다. 건화 측 확인이 필요한 사항.
4. **이격 시설별 분리** — S3이 dyn에서 닫히면 워크벤치도 시설별 이격으로 확장.
