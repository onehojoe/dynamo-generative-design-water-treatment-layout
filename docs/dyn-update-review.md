# dyn 업데이트 가능성 검토 — 2500726 정수장 python 최적화 v1

2026-08-24, 그래프 JSON 직독 분석 기준(354노드/02공간본 · 347노드/AU본).
원본을 고치기 전에 읽는 문서다. 항목마다 **근거 → 제안 → 리스크** 순.

## 1. ★GD 스터디 미결선 (가장 큰 결함)

- **근거**: 두 판본 모두 `IsSetAsInput` / `IsSetAsOutput` 마킹이 **0개**. GenerativeDesign
  패키지(6.1.1.0)는 물려 있으나, Generative Design 스터디는 Input/Output 선언 없이는
  슬라이더를 탐색하지도, Count·Length&Cost를 비교하지도 못한다.
  (AU 발표의 Outcome 그리드 캡처는 별도 결선본 또는 시연본으로 추정 — 배포 dyn에는 없다.)
- **제안**: IntegerSlider 11개 → Is Input 체크, Count·Length&Cost 워치 → Is Output 체크.
  강의 커리큘럼 03장("Input으로 선언하지 않은 값은 탐색되지 않는다")의 실물 예제가 된다.
- **리스크**: 낮음. 그래프 로직 무변경.

## 2. ★List.Shuffle 무시드 → 재현성 없음

- **근거**: Dynamo `List.Shuffle`은 시드 인자가 없다. 같은 슬라이더 값이라도 실행마다
  셔플 순서가 달라질 수 있다 → **GD 스터디에서 "같은 입력 = 같은 출력"이 깨진다.**
  솔버가 같은 지점을 두 번 평가하면 다른 점수가 나오는 구조는 최적화를 방해한다.
- **제안**: 셔플을 시드 기반으로 교체 — 방법 A) `List.SortByKey` + 시드 해시 키(노드만으로 가능),
  방법 B) Python 한 줄(`random.Random(seed).shuffle`). 워크벤치 `js/engine.js`의 mulberry32가
  동작 사양의 참고 구현.
- **리스크**: 기존 저장 대안과 배치가 달라진다(재현성 확보의 대가). 교육 관점에선 필수 교정.

## 3. rec0~rec10 11회 복붙 구조

- **근거**: "박스 배치" 그룹이 11번 반복(노드 354개의 대부분). 02공간본의 Python 노드(4,325자)가
  같은 로직의 루프 구현 시도인데, AU본에서는 **제거**됐다.
- **제안**: Python 루프 단일화 시 354노드 → 약 80노드 예상. 단, 교육용으로는 복붙 구조가
  "단계별로 보인다"는 장점도 있으므로 **강의용(복붙 유지) / 실무용(루프) 두 판 분리**를 권장.
- **리스크**: Python화하면 GD 헤드리스 실행에서 CPython 엔진 로드가 추가된다(17번 프로젝트에서
  GD+패키지 충돌 전례 있음 — DynamoFormaBeta 사례). 결선 전에 단독 실행 검증 필수.

## 4. Remember 캐시 관리

- **근거**: 02공간본은 캐시 보유(대지경계·박스·출입·참조점 = 워크벤치 데이터 원천),
  **AU본은 캐시 전부 EMPTY** → AU본은 Revit 모델 없이는 못 돈다.
- **제안**: "캐시 보유 저장본"을 정본으로 유지하고 배포·교육 시 그 판을 쓸 것.
  Select Model Element 4개는 특정 rvt의 요소 ID에 묶여 있으므로, rvt가 바뀌면 재선택 필요.
- **리스크**: 없음(관리 규칙일 뿐).

## 5. 미구현 주석 항목 (원저자 스스로 표시)

- **근거**: 그룹 주석 "추후 지형, 이격 관련 추가해야함" · "추후 도로 및 이동 관련 추가해야함".
  이격은 사실 `Curve.OffsetMany`(10·15 값)로 제외영역에 이미 부분 구현돼 있다.
- **제안**: ①이격값을 슬라이더로 승격(시설별 법정 이격 반영 준비) ②도로·이동은 같은 폴더의
  `autorouting v2/v3.dyn`과 합류하는 별도 단계로(2단계 검토 대상) ③지형은 AU 발표 후반부
  (경사지 3D·중력흐름) 스코프 — 배치 dyn에 넣지 말고 후속 그래프로 분리 권장.
- **리스크**: 이격 슬라이더는 낮음. 도로/지형은 스코프 확장이므로 별도 승인 후.

## 6. 성능

- **근거**: 배치 1회당 `Geometry.DoesIntersect`/`Intersect`를 기배치 전수와 대조. 후보점
  2,601개(51×51) × 박스 11 × 제외영역이면 Dynamo 프리뷰 포함 시 수 초~수십 초.
- **제안**: BBox 프리체크(BoundingBox 겹침 먼저, 통과 시에만 정밀 교차) + 프리뷰 OFF.
  17번 프로젝트에서 실증된 패턴.
- **리스크**: 낮음.
